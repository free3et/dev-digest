## 1. Key decisions (spec C-23…C-28, plan R1–R7)

- C-23 stored `PrBrief.risks` = `Risks` wrapper `{risks: Risk[]}`; model output `risks` = flat `Risk[]`; `groundBrief` maps one to the other.
- C-24 new module `server/src/modules/brief/` reads other modules only via container getters (`reviewRepo`, `repoIntel`, `contextDocs`, `contextDocLinksRepo`, `agentsRepo`, `priceBook`, `llm()`, `github()`); small pure pieces duplicated on purpose with a `// duplicated from <path>` comment.
- C-25 `linked_issue` / `context_docs` are "missing" only when referenced/attached but unreadable.
- C-26 linked issue = one live `github.getIssue` for the first same-repo reference, 8 s timeout; failure/no token → `missing_inputs`. Not an LLM call.
- C-27 `line` only goes into the URL; no scroll-to-line.
- C-28 AC-25 guard = in-process `Set<pr_id>`, released in `finally`.
- R1 sync only `contracts/brief.ts` and `contracts/review-api.ts` into the client vendor copy (byte-identical); leave other drifted vendor files alone.
- R2 assembly, budget, grounding = pure functions in `brief/helpers.ts` with unit tests.
- R3 copy the `ensureIntent` cancellation pattern (`cancelled` flag checked before upsert; `server/src/modules/reviews/intent-deriver.ts:91,124-131`).
- R5 it-tests: `structuredBySchema: { pr_brief: … }` and override both `openai` and `openrouter` providers (default `risk_brief` is `openai`).
- R6 invalidate `["pr-brief", prId]` when a run settles.
- R7 remove dead keys `brief.block.history`, `brief.noHistory`, `brief.overlap` (after grep for callers).
- RQ1 resolved: reuse `wrapUntrusted` from `@devdigest/reviewer-core` plus the fixed `SECURITY:` system line, as `intent-helpers.ts` `buildClassifierMessages` does (`:21,263-288`).
- `PrHistoryItem` / `PrHistory` stay exported; only the `history` field leaves `PrBrief` (NG-2).

## 2. Architecture constraints

- onion-architecture: `routes.ts` validates + one service call + `schema.response`; `service.ts` orchestrates over ports; only `repository.ts` imports drizzle/db schema; pure rules in `helpers.ts`; no import of another module's service/repository/routes/helpers (`resolveFeatureModel` from `settings/feature-models.ts` is the allowed exception). One upsert, no transaction.
- Register module in `server/src/modules/index.ts`. Errors: `AppError('brief_unavailable'|'brief_in_progress', …, 409)`, `NotFoundError` for foreign PR. Bad `:id` → 422.
- frontend-ui-architecture: data via `client/src/lib/hooks/brief.ts` → `src/lib/api.ts`; card in `OverviewTab/PrBriefCard/` with nested sub-folders; strings in `messages/en/brief.json` as nested camelCase.
- Contracts first (server copy, then byte-identical client copy); wire fields snake_case.
- Do not touch: migrations, `server/src/platform/{prompt,grounding,structured}.ts`, `server/clones/**`, `client/src/vendor/ui/**`, lockfiles, vendor files other than the four in W0, `FEATURE_MODELS.risk_brief` default (NG-4).

## 7. Risks and traps

- No abort signal on the LLM port: the 30 s race leaves the call running and billed; persistence must check `cancelled` (EC-7).
- Paid calls in tests: mock both `openai` and `openrouter`; register the `pr_brief` fixture name or the mock throws "fixture failed schema".
- Docker-less "green": `*.it.test.ts` self-skip without Docker; the T17 gate must see "passed". `pnpm typecheck` excludes `server/test/**`.
- Polled-only PR: `pr_files` empty → blast degraded, no file stats (expected, AC-11). Open the PR once before the demo.
- Duplicated pure code (C-24): "latest review per agent" now exists in 4 places; a change must reach all four.
- Strict json_schema: `.nullable()` not `.optional()`, no min/max; field order is generation order, summary last.
- Vendor copy: server first, byte-identical copy; do not fix other drifted files.
- Client: `mockFetch` cannot return 409 (`vi.stubGlobal`); no `user-event` (`fireEvent`); `pnpm build` breaks a running `next dev`; ellipsis on title and path.
- Bad `:id` → 422, not 400.
- In-flight `Set` is per process (C-28).
- Dev DB may have drifted: verify `pr_brief` with `psql \d`; write no migration.

## 8. Demo checklist (run on `./scripts/dev.sh`, real provider key, PR opened once)

1. **Generate:** Overview of a PR without a brief shows unavailable text + Generate brief → click → disabled/generating → summary, Merge risks, Review focus; server log shows one brief line.
2. **Risks:** sorted High → Medium → Low, text-labelled pills, long paths ellipsized; IntentCard list reads "Intent risk areas"; brief full width above Intent | Blast.
3. **Review focus → file:** click or Tab+Enter → URL `?tab=diff&file=…(&line=…)`, file expanded and scrolled in Smart and original order; blast-only file shows "not in this diff".
4. **Cache:** reload → brief appears instantly, no new brief log line, same model/cost footer.
5. **Refresh / stale:** Refresh on fresh brief asks to confirm (cancel does nothing); after a new commit + re-sync the stale notice shows and Refresh regenerates without a dialog.
6. **Missing inputs / failure:** PR without intent row or with degraded blast still generates, muted "Generated without: …"; with the provider key removed, Generate shows inline error + Retry and keeps the previous brief.
