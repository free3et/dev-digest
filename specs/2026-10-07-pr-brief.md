# Spec: PR Brief | Spec ID: SPEC-2026-10-07-pr-brief | Status: approved
Supersedes: — (extends the Overview "PR Brief" section of `docs/specs/intent-layer.md`, which left the brief beyond Intent out of scope)
Modules: server, client, `@devdigest/shared`
Approved: free3et, 2026-10-07

## Problem and user

A reviewer opening a pull request has to read the whole diff before knowing what
the PR does, where it can break and where to start reading. The Overview tab
already shows the PR's derived Intent and its Blast radius side by side (D-2),
but nothing turns those facts into a short orientation: a summary, the merge
risks and a reading order. The user is the reviewer of a PR in DevDigest
studio.

## Goals / Non-goals

- **G-1** On the PR Overview tab, one PR Brief card shows a short summary (what
  the PR does and why), merge risks (title, file, severity) and a review focus
  list (`file:line — reason`, in reading order).
- **G-2** The brief is generated on request with exactly one model call over
  precomputed facts, never over diff hunk bodies.
- **G-3** A generated brief is cached per PR and head commit: reloading shows it
  with no model call; a Refresh regenerates it.
- **G-4** Every file the brief names is a file of the PR or of its blast map; the
  model cannot introduce a path.
- **G-5** Clicking a review-focus item opens that file in Files changed.
- **G-6** When Intent, Blast radius or other inputs are missing, the brief is still
  generated and says which inputs were missing.
- **NG-1** No VerdictBanner (verdict + PR score) in the brief and no expandable
  risk explanations (homework P3) — follow-up spec.
- **NG-2** No "Prior PRs touching these files" (PR history); `history` leaves the
  brief contract.
- **NG-3** The brief never derives Intent or computes Blast radius itself; it only
  reads what already exists (a second model call would break G-2).
- **NG-4** The `risk_brief` default model (`openai` / `gpt-4.1`) is not changed by
  this spec, although the Settings picker can only re-select OpenRouter models
  (`client/INSIGHTS.md` 2026-09-25) — follow-up.
- **NG-5** No brief cost in `agent_runs.cost_usd`, in the PR-list cost or in the run
  trace; a brief is not an agent run.
- **NG-6** No locale other than English (`client/messages/` holds only `en`).
- **NG-7** IntentCard's own risk-area list is not removed (only relabelled, AC-21).

## User stories

- **US-1** As a reviewer, I open a PR without a brief, click Generate brief and read
  a summary, the merge risks and where to start.
- **US-2** As a reviewer, I click a review-focus item and land on that file in Files
  changed.
- **US-3** As a reviewer, I reload or come back later and see the same brief
  instantly, without paying for it again.
- **US-4** As a reviewer of a PR that got new commits, I see that the brief is stale
  and refresh it.

## Workflow and communication

```mermaid
sequenceDiagram
  participant UI as Client (Overview tab)
  participant API as server brief module
  participant DB as pr_brief table
  participant F as Precomputed facts (pr_intent, blast, smart-diff, PR detail, attached context docs; linked issue via live GitHub read)
  participant LLM as LLM provider (risk_brief model)
  UI->>API: GET /pulls/:id/brief
  API->>DB: read row
  API-->>UI: {brief | null, stale}
  UI->>API: POST /pulls/:id/brief (Generate / Refresh)
  API->>F: read facts (no diff hunk bodies)
  API->>API: assemble input, at most 8,000 tokens
  API->>LLM: one structured call
  LLM-->>API: {risks, review_focus, summary}
  API->>API: ground files and lines, cap, sort
  API->>DB: upsert brief with head_sha
  API-->>UI: PrBrief
```

## Contracts

| Contract | Change | Shape |
|---|---|---|
| `PrBrief` (`@devdigest/shared/contracts/brief.ts`, server copy first, then `client/src/vendor/shared/contracts/brief.ts`) | changed | `summary`: string · `risks`: `Risks` (unchanged item shape: `kind` free string, `title`, `explanation`, `severity` high/medium/low, `file_refs` list of paths) · + `review_focus`: list of {`file`: string, `line`: integer, nullable (null = no grounded line), `reason`: string} · `intent`: `Intent`, now nullable (null = no derived intent) · `blast`: `BlastRadius`, now nullable (null = blast unavailable) · − `history` removed · + `head_sha`: string (PR head the brief was generated for) · + `generated_at`: ISO string · + `model`: string · + `cost_usd`: number, nullable (null = model unpriced) · + `missing_inputs`: list of `intent` / `blast` / `smart_diff` / `linked_issue` / `context_docs` · + `intent_stale`: boolean (intent was derived for an earlier head) · + `truncated_inputs`: list of `intent` / `context_docs` / `linked_issue` / `description` / `blast_callers` / `file_stats` |
| Brief model output (`brief.ts`) | new | `risks`: list of `Risk`; `review_focus`: list of {`file`, `line` nullable, `reason`}; `summary`: string — declared in this order; nullable, never optional |
| `GET /pulls/:id/brief` → `PrBriefResponse` (`review-api.ts`) | new | response `{brief: PrBrief, nullable (null = never generated), stale: boolean (true = cached `head_sha` ≠ current PR head)}`; 404 unknown PR |
| `POST /pulls/:id/brief` → `PrBrief` | new | no body; 200 with the new brief; 404 unknown PR; 409 `brief_unavailable` when no brief can be produced; 409 `brief_in_progress` while another generation for the PR runs; 429 above the rate limit |
| `pr_brief` table | unchanged | `pr_id` + `json`; everything above lives inside `json`; no migration |
| `PrIntentResponse`, `BlastRadiusResponse`, `SmartDiffResponse`, `PrDetail`, `FeatureModelId.risk_brief` | unchanged | read as inputs |
| Client URL state of the PR page | changed | `?tab=diff` + new `file=<path>` and optional `line=<n>` |

The stored `PrBrief.risks` stays the existing `Risks` wrapper (`{risks: Risk[]}`), while the brief model output's `risks` is a flat `Risk[]` list; the server maps the model's flat list into the stored wrapper (C-23).

## Acceptance criteria (EARS)

Server

- **AC-1** — WHEN `GET /pulls/:id/brief` is called for a PR with a stored brief, the API SHALL return that brief without calling the LLM.
  - Source: G-3, US-3, D-1
  - Verify: integration (`*.it.test.ts`) — seed a `pr_brief` row; response equals it; mock LLM records 0 calls
- **AC-2** — WHEN `GET /pulls/:id/brief` is called for a PR with no stored brief, the API SHALL return `{brief: null, stale: false}`.
  - Source: US-1, C-2
  - Verify: integration — fresh PR → exact body
- **AC-3** — WHILE the stored brief's `head_sha` differs from the PR's current head, `GET /pulls/:id/brief` SHALL return the stored brief with `stale: true`.
  - Source: US-4, C-3
  - Verify: integration — change `pull_requests.head_sha` after seeding; `stale` is true, LLM 0 calls
- **AC-4** — WHEN `POST /pulls/:id/brief` is called, the API SHALL make exactly one structured LLM call, with no reprompt, using the model resolved for the `risk_brief` feature in the PR's workspace.
  - Source: G-2, D-1, C-6
  - Verify: integration — mock LLM records 1 call with the workspace override model; a mock returning invalid output is not called a second time
- **AC-5** — WHEN `POST /pulls/:id/brief` succeeds, the API SHALL store the returned brief in `pr_brief` with `head_sha` equal to the PR head at generation time, replacing any earlier brief of that PR.
  - Source: G-3, D-1
  - Verify: integration — row `json.head_sha` = PR head; second POST leaves one row
- **AC-6** — The model input assembled for `POST /pulls/:id/brief` SHALL be at most 8,000 tokens (`ceil(characters / 4)`), reached by removing content in this order until it fits: (1) Project Context documents, whole documents, last-attached first; (2) linked-issue body; (3) PR description, from its end; (4) blast callers, lowest-ranked first; (5) changed-file stats, boilerplate and docs roles first, then smallest change first.
  - Source: G-2, C-6, NFR-2
  - Verify: unit — oversized fixture → estimate ≤ 8,000 and the removed parts follow the order; `truncated_inputs` lists them
- **AC-7** — The model input SHALL contain no diff hunk content (no `PrFile.patch` text) — only paths, roles and addition/deletion counts.
  - Source: G-2, D-1
  - Verify: unit — fixture patches carry a marker string; the assembled messages do not contain it
- **AC-8** — WHEN the model returns a risk `file_refs` entry or a review-focus `file` that is neither a changed file of the PR nor a file in its blast map, the API SHALL drop that entry before storing (a risk left with no `file_refs` is dropped).
  - Source: G-4, D-1
  - Verify: unit — model fixture with an invented path → absent from the brief
- **AC-9** — IF a review-focus `line` does not equal a blast caller line, an intent risk-area line or a Smart Diff finding line of the same file, THEN the API SHALL store that item with `line: null`.
  - Source: G-4, C-4
  - Verify: unit — known line kept, unknown line → null, item kept
- **AC-10** — The stored brief SHALL hold at most 6 risks, ordered high → medium → low (ties in model order), and at most 8 review-focus items in model order.
  - Source: G-1, C-10, C-11, C-13
  - Verify: unit — 9 risks / 10 items fixture → 6 sorted / first 8
- **AC-11** — IF Intent, Blast radius, Smart Diff, the linked issue or Project Context documents are unavailable (the linked issue and Project Context documents count as unavailable only when referenced / attached but unreadable), THEN `POST /pulls/:id/brief` SHALL still produce a brief whose `missing_inputs` names each unavailable input.
  - Source: G-6, D-1, C-5, C-25, C-26
  - Verify: integration — PR with no `pr_intent` row and degraded empty blast → 200, `missing_inputs` contains `intent` and `blast`, `intent` and `blast` null
- **AC-12** — IF the LLM call fails, times out after 30 s, refuses or returns output that fails the schema, or no provider key is configured, THEN `POST /pulls/:id/brief` SHALL answer 409 `brief_unavailable` and leave the stored brief unchanged.
  - Source: G-3, C-6, §7a failure
  - Verify: integration — seed a brief, mock LLM throws / delays past timeout → 409, row identical
- **AC-25** — IF `POST /pulls/:id/brief` is called while another generation for the same PR is in flight, THEN the API SHALL answer 409 `brief_in_progress` without calling the LLM.
  - Source: EC-8, C-20, C-28
  - Verify: integration — mock LLM held open on the first POST; a second POST → 409 `brief_in_progress`, mock LLM records 1 call
- **AC-26** — IF the never-cut parts of the model input (intent, PR title, totals, system prompt) alone exceed 8,000 tokens, THEN the API SHALL shorten the intent text until the input fits, mark `intent` in `truncated_inputs`, and still make the call.
  - Source: EC-9, C-21, C-6
  - Verify: unit — oversized intent fixture → estimate ≤ 8,000, intent shortened, `truncated_inputs` contains `intent`

## Edge cases

- **EC-1** PR polled but never opened: no changed files are stored, so the brief has no file stats and blast is empty → AC-11 (`missing_inputs` contains `blast`, `smart_diff`).
- **EC-2** Every model risk/focus item names an invented file → AC-8 leaves empty lists; card shows `noRisks` and a "no review focus" line → AC-15.
- **EC-3** 300+ changed files or very long Project Context documents → AC-6.
- **EC-4** Focus item points at a blast-map caller file that is not in the diff → AC-18.
- **EC-5** Long file paths in risk and focus rows must ellipsize, not wrap the title (`client/INSIGHTS.md` 2026-09-26) → AC-15 (Verify: row style test).
- **EC-6** PR head moves while a brief is cached → AC-3, AC-20.
- **EC-7** Timeout while the provider call is still billed in flight (`server/INSIGHTS.md` 2026-09-25) → AC-12 (nothing persisted after the timeout).
- **EC-8** Two POSTs for the same PR at once (double click, two tabs) → AC-14 (double click), AC-25 (second request).
- **EC-9** Non-truncatable core (intent, PR title, totals, system prompt) alone exceeds 8,000 tokens → AC-26.
- **EC-10** Intent exists but was derived for an earlier head → used, `intent_stale: true` (C-5) → AC-11 Verify extended; shown in the muted line → AC-22.
